MAAT ETC

Prácticas · CSIC · IAA · 2026

Versión web de la calculadora de tiempos de exposición del instrumento MAAT para el Gran Telescopio Canarias, hecha durante mis prácticas en el Instituto de Astrofísica de Andalucía. Llevé el script de escritorio en Python del equipo científico a una aplicación Flask: el formulario envía los parámetros de observación, el servidor calcula la relación señal/ruido o el tiempo de exposición y devuelve la gráfica generada con matplotlib. Los parámetros también se pueden cargar desde un archivo .txt, y la aplicación se sirve con Gunicorn y Nginx.

Cómo trabajo

Pienso mucho antes de escribir la primera línea. Cuando por fin programo, ya sé qué voy a usar y de qué forma.

  1. Planteo el problema

    Antes de tocar nada lo escribo entero: qué hay que resolver, para quién y con qué límites.

  2. Investigo las tecnologías

    Busco las que son compatibles con la solución y estudio las ventajas y desventajas de cada una.

    Laravel

    Elegido en Swimming Up

    • Autenticación y roles de serie
    • ORM y migraciones
    • Pesado para algo pequeño

    Flask

    Elegido en MAAT ETC

    • Ligero y directo
    • El mismo lenguaje que el script científico
    • Casi todo se monta a mano

  3. Trazo una ruta

    Con la tecnología elegida, dibujo un camino posible hasta la solución, paso a paso.

  4. Divido el proyecto en partes

    Partes bien diferenciadas, para trabajar mejor en cada una y para que un error en una no arruine el proyecto entero.

    Toca una parte para romperla.

    Error en: API. Las demás partes siguen funcionando.

  5. Abro el repositorio

    Git y GitHub llevan el control de versiones: cada cambio queda guardado y siempre puedo volver atrás.

    • main
    • una rama por cada parte

  6. Hasta aquí, ni una línea de código.

    Solo empiezo a programar cuando tengo claro qué voy a utilizar y de qué forma.

  7. Programo por versiones

    Ahora sí. Construyo cada parte y voy cerrando versiones pequeñas, una detrás de otra.

    1. v0.1
    2. v0.2
    3. v0.3

  8. Pruebo y corrijo

    Pruebo cada versión en entornos virtuales con Vagrant y Docker, corrijo los errores y repito hasta que funciona.

    $ vagrant up
$ docker compose up --build

  9. La llevo a un entorno real

    Solo la versión funcional sale de la máquina virtual. Ahí es donde la pruebo de verdad.

Cómo uso la IA

A día de hoy, tal y como yo lo veo, usar IA para desarrollar software ya no es opcional si no quieres quedarte atrás.

Cuánto la uso depende de cuánto domino cada tecnología.

Tecnología nueva

Primero la aprendo yo. Investigo por mi cuenta, leo la documentación y sigo tutoriales hasta ser capaz de manejarla sin ayuda de la IA.

Sin IA, todavía

Tecnología que domino

Entonces sí. Con Claude y Claude Code desarrollo más rápido y con menos errores, porque sé revisar cada cambio que proponen.

Con IA

Nada de cajas negras.

No quiero un proyecto que solo sepa desarrollar la IA. Entiendo qué está construyendo y por qué, para poder corregirla o decidir otro camino en cualquier momento.

Así las aplicaciones que hago salen más fiables, más eficientes y más fáciles de mantener.
